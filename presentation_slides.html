🎯 ทำเพื่ออะไร (Purpose)

เพื่อสร้างระบบซื้อขายฮาร์ดแวร์ไอทีที่ทนทาน (Resilient) และมีความปลอดภัยทางการเงินสูง รองรับการเลือกสเปกคอมพิวเตอร์ที่หลากหลาย

💡 ตอบโจทย์ Solution อะไร (The Solution)

แก้ปัญหาเว็บช้าและค้างเวลาค้นหาสินค้า ป้องกันการถูกดัดแปลงราคาสินค้าจากหน้าบ้าน (Frontend tampering) และเพิ่มความง่ายในการจัดส่งด้วยระบบกรองที่อยู่เริ่มต้น

Business Model Canvas (BMC)

Business Strategy

🤝 Key Partners

  • ผู้ผลิต/ตัวแทนจำหน่ายฮาร์ดแวร์ไอที (ASUS, Intel, AMD, Acer)
  • ผู้ให้บริการรับชำระเงิน (PromptPay Gateway)
  • บริษัทขนส่งพัสดุ (Kerry, Flash Express)

⚡ Key Activities

  • จัดหาและคัดกรองสเปกอุปกรณ์คอมพิวเตอร์คุณภาพ
  • พัฒนาระบบความปลอดภัยและการซื้อขาย
  • ปรับปรุงระบบหลังบ้าน (CMS/Inventory)

💎 Value Propositions

  • ค้นหาและกรองสเปกสินค้าไอทีได้ละเอียดที่สุด
  • ความปลอดภัย 100% ป้องกันการแก้ราคาซื้อขาย
  • มีแผงจัดการหลังบ้านที่ยืดหยุ่นสูง

❤️ Customer Relationships

  • บริการหลังการขายและการรับประกันสินค้า
  • ระบบติดตามออเดอร์เรียลไทม์
  • ระบบแก้ไขข้อมูลส่วนตัวสะดวกรวดเร็ว

👥 Customer Segments

  • เกมเมอร์ (Gamers)
  • โปรแกรมเมอร์ & ครีเอเตอร์
  • องค์กร/ผู้จัดหาสเปกคอมพิวเตอร์สำนักงาน
  • ผู้ใช้ทั่วไปที่หาอะไหล่ไอที

🔑 Key Resources

  • ระบบฐานข้อมูลสเปกสินค้าไอที
  • ซอฟต์แวร์ระบบคลังและระบบแอดมิน
  • เครื่องมือตรวจสอบการจ่ายเงินปลายทาง

📢 Channels

  • หน้าเว็บไซต์หลัก (Web Application - React)
  • เครือข่ายสังคมออนไลน์ (Social Media)
  • กลุ่มคอมมูนิตี้คนจัดสเปกคอมพิวเตอร์

💸 Cost Structure

  • ค่าดูแลระบบโฮสติ้งและฐานข้อมูล
  • งบประมาณการจัดซื้อและบริหารคลังสินค้า
  • ค่าธรรมเนียมธุรกรรมการเงิน/บริการ PromptPay

💰 Revenue Streams

  • รายได้จากการขายสินค้าไอที/โน้ตบุ๊กโดยตรง
  • ค่าพรีเมียมจากบริการจัดสเปกคอมพิวเตอร์สั่งประกอบ
  • รายได้เสริมจากป้ายโฆษณา (Banners) หลังบ้านระบบ CMS

System Design & Secure Data Flow

Architecture Pattern
sequenceDiagram autonumber actor Customer participant Frontend as React App (Vite) participant Backend as API Server (Node) participant DB as Database (Postgres) Customer->>Frontend: กดสั่งซื้อสินค้าในตะกร้า Note over Frontend: ป้องกันแฮกเกอร์แอบแก้ราคาหน้าบ้าน Frontend->>Backend: ส่งออเดอร์และรายการสินค้า (ไม่มีราคาส่งไป) Backend->>DB: ดึงราคาจริง ณ ขณะนั้นมาคำนวณ DB-->>Backend: ราคาจริงของสินค้า Backend->>Backend: สรุปยอดรวมที่ปลอดภัย (Financial Snapshot) Backend->>DB: สร้างออเดอร์และล็อกสถานะรอจ่ายเงิน Backend-->>Frontend: ส่งลิงก์และ PromptPay QR ยอดชำระจริง Frontend-->>Customer: แสดง QR Code ยอดเงินแท้จริง

การป้องกันช่องโหว่ด้านราคา (Security-First)

ระบบอีคอมเมิร์ซแบบเดิมมักส่งคำสั่งซื้อพร้อมราคาประมวลผลจากหน้าบ้าน (เช่น ส่งออเดอร์ราคา 100 บาทที่ถูกแฮกแก้ข้อมูลมา)

Project JAMINE แก้ปัญหานี้อย่างไร: หน้าบ้านจะส่งไปเพียง ID สินค้า และจำนวนที่จะซื้อเท่านั้น จากนั้นตัว API Server หลังบ้านจะดึงราคาจริงในฐานข้อมูลมาสแน็ปช็อตและบวกเลขคำนวณเอง ทำให้แฮกเกอร์ไม่มีทางเจาะราคาสินค้าได้สำเร็จ

API Specifications & Endpoints

API Integration Guide
Method Endpoint ลักษณะการทำงาน (Description) ความปลอดภัย (Auth Policy)
POST /api/v1/auth/login เข้าสู่ระบบและผูกสิทธิ์ของผู้ใช้ เปิดสาธารณะ / ส่งกลับคุกกี้ Secure HTTP-only
POST /api/v1/auth/register สมัครสมาชิกใหม่เข้าระบบ เปิดสาธารณะ
GET /api/v1/products ดึงรายการสินค้าคอมพิวเตอร์พร้อมระบบค้นหาและกรองสเปก เปิดสาธารณะ / รองรับ Caching Query
POST /api/v1/checkout สร้างและสแน็ปช็อตออเดอร์ ตรวจสอบราคาจริง 🔒 ต้องล็อกอิน (JWT Token verification)
GET /api/v1/admin/orders ดึงประวัติยอดคำสั่งซื้อทั้งหมดหลังบ้าน 🔒 เฉพาะผู้ดูแลระบบ (Admin Role Guard)
POST /api/v1/payment/verify ตรวจสอบยอดสแกนจ่าย PromptPay แบบอัตโนมัติ 🔒 ต้องล็อกอิน

โครงสร้างข้อมูลและโมเดลหลัก (Data Schemas)

Database Models

👤 User Model

  • id (String, UUID)
  • email (String, Unique)
  • password (String, Hash)
  • role (Enum: CUSTOMER, ADMIN)

📦 Product Model

  • id (String, UUID)
  • name (String)
  • price (Decimal, Precision 2)
  • stock (Integer)
  • specs (JSON/Text - CPU, RAM, GPU)
  • category (String)

🛒 Order Model

  • id (String, UUID)
  • user_id (String, FK)
  • total_amount (Decimal)
  • status (Enum: PENDING, PAID, SHIPPED)
  • items (Array of Product Snapshots)
