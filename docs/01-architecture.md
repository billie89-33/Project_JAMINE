# 🏗️ 01. Architecture & Directory Structure

เราใช้สถาปัตยกรรมแบบ **Modular Feature-driven (Enterprise Standard)** เพื่อให้โค้ดสะอาด มีความปลอดภัยสูงสุด และรองรับการสเกลระบบขนาดใหญ่

## 📂 Directory Structure
แบ่งแยกขาดออกจากกันระหว่าง **shared** (ส่วนกลาง) และ **modules** (ส่วนฟีเจอร์)

### 1. `src/shared/` (The Kernel)
- `components/`: UI พื้นฐาน (Button, Input) และ **Shared Business Components** (เช่น OrderSummaryCard) ที่ต้องใช้งานร่วมกันในหลายโมดูล
- `contexts/`: Global State (Auth, Cart, Theme)
- `hooks/`: ตรรกะที่ใช้ร่วมกัน เช่น `useApi`, `useDebounce`
- `api/`: การตั้งค่า `apiClient.js` (Axios Instance) และการทำ Interceptors
- `utils/`: ฟังก์ชันคำนวณและฟอร์แมตข้อมูล (Currency, Date)
- `constants/`: ตัวแปรคงที่และ Enums (Status, Roles)

### 2. `src/modules/` (The Features)
แต่ละโมดูลต้องเป็นอิสระต่อกัน (Encapsulated) มีโครงสร้างดังนี้:
- `components/`: UI เฉพาะของฟีเจอร์นั้นๆ
- `hooks/`: ตรรกะจัดการสถานะของฟีเจอร์ (Custom Hooks)
- `services/`: ไฟล์ API ของโมดูลนั้นๆ เท่านั้น
- `index.js`: **Barrel File** สำหรับส่งออกสิ่งที่อนุญาตให้ภายนอกใช้งานได้

### 3. `src/layouts/` & `src/pages/`
- **Layouts**: โครงสร้างหน้า (UserLayout, AdminLayout)
- **Pages**: จุดรวมตัวของ Modules และ Layouts เพื่อสร้าง Route (ห้ามเขียน Logic ยาวเหยียดในนี้)

## 🚀 มาตรฐานการสื่อสารข้อมูล
- **One-Way Data Flow:** Data (Backend) -> Service -> Hook (State) -> Component (UI)
- **SSOT (Single Source of Truth):** ข้อมูลตะกร้าสินค้าหรือสิทธิ์ผู้ใช้ต้องอยู่ที่ Context เดียวเท่านั้น ห้ามกระจาย State ไปไว้ที่อื่น
